## 3. 验收标准（Definition of Done）

### 3.1 功能验收（对应需求）
- [ ] 创建契约后，按配置的匹配规则（方法/路径/头/查询/body）命中并返回动态响应；
- [ ] 同一契约多场景可手动激活切换，切换后新请求立即生效；
- [ ] after_calls 自动切换与 cron 定时切换可观测（切换记录可查）；
- [ ] 每次调用均有记录，管理 API 可分页/过滤查询，未命中也有记录；
- [ ] 延迟（固定/随机）与故障（概率/序号/固定错误）注入生效且写入记录字段；
- [ ] 记录清理任务按保留期自动清理；
- [ ] 仪表盘显示统计与任务健康状态。

### 3.2 工程验收（对应硬性要求）
- [ ] **分层**：handler→service→repository→database 单向依赖，无反向引用；
- [ ] **数据库迁移**：启动自动迁移，幂等可重复，迁移文件随仓库分发；
- [ ] **API**：管理 API 与模拟 API 行为与 04 文档一致，统一信封；
- [ ] **后台任务**：三个任务注册运行，`/admin/api/health` 可查 last_run；
- [ ] **测试**：`go test ./... -race` 全绿，全局覆盖率 ≥ 70%；
- [ ] **完整构建验证**：`make verify` 七步全绿（fmt/vet/lint/test/build/check-size/smoke）；
- [ ] **规模约束**：Go 非测试行数 2000 < L < 2200（目标 2150±20）；文件数 20 < F < 25（目标 23）。

### 3.3 质量验收
- [ ] 无数据竞争（`-race` 零告警）；
- [ ] 模拟热路径在无注入延迟时 P95 < 20ms（本机）；
- [ ] 前端无需构建链，`go run` 后直达 `/admin/` 可用。

## 4. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 实现后行数越界 | 中 | 硬性验收失败 | 09 文档熔断流程 + `make verify` 每步计量，尽早暴露 |
| JSONPath/模板实现复杂度超预期 | 中 | 行数上溢 | 按 05 文档"简化实现"定义收敛（仅支持 `$`/`.`/`[N]`/`[*]`） |
| 场景并发切换竞态 | 低 | 数据不一致 | 事务切换 + 快照原子替换 + race 测试兜底 |
| SQLite 单写者导致记录写入慢 | 中 | P95 上升 | 异步批量写入 + 分批删除 + PRAGMA journal_mode=WAL |
| 前端需求膨胀 | 低 | 范围蔓延 | 严格按 06 文档实现，超出项记录 backlog 不实现 |

## 5. 退出条件（Exit Criteria）

1. 13 个任务全部完成且 DoD 勾选完毕；
2. `make verify` 在干净环境（`git clean -fdx` 后）一次通过；
3. 行数/文件数计量输出落在合规区间并在 09 文档登记；
4. 冒烟脚本输出全部 `[PASS]`；
5. 本套文档与实际实现无冲突（文档一致性复核通过）。

## 6. 文档变更纪律

- 本文档集是实现的唯一依据；实现偏离设计时必须**先改文档、再改代码**；
- 每个里程碑结束时更新本文档的进度勾选；
- 规模预算任何调整须登记于 09 文档第 5 节流程。
