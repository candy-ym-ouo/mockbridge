# 02 总体架构设计

## 1. 架构目标

- **分层清晰、单向依赖**：`handler → service → repository → database/model`，任何一层不反向依赖；
- **领域逻辑可测试**：匹配引擎、响应引擎、场景切换逻辑与 HTTP/DB 解耦，可纯单元测试；
- **模拟路径高性能**：热路径（请求匹配 → 场景快照 → 响应渲染）避免不必要的锁与 IO；调用记录异步落库；
- **满足规模约束**：22 个 Go 文件、约 2150 行非测试代码，每个文件职责单一、可独立评审。

## 3. 模块职责说明

### 3.1 handler 层
| 文件 | 职责 |
| --- | --- |
| `internal/handler/mock_handler.go` | 模拟入口：接收任意路径请求 → 调 MockService.Handle → 写出响应 |
| `internal/handler/admin_handler.go` | 管理 API：契约/场景/记录/统计/健康 全部 CRUD 端点 |
| `internal/middleware/middleware.go` | RequestID 生成、访问日志、panic 恢复（返回 500）、CORS、静态文件托管 |

### 3.2 service 层
| 文件 | 职责 |
| --- | --- |
| `internal/service/mock_service.go` | 模拟主流程编排：读取快照 → 匹配 → 渲染 → 故障/延迟 → 记录（最核心） |

| `internal/service/scenario_service.go` | 场景 CRUD、手动/自动切换、切换记录 |
| `internal/service/record_service.go` | 调用记录写入队列、分页查询 |
| `internal/service/stats_service.go` | 统计聚合查询与聚合任务入口 |

### 3.3 纯逻辑引擎（无外部依赖，可单测）
| 文件 | 职责 |
| --- | --- |

## 4. 模拟请求处理时序（核心路径）

```
客户端 ──HTTP──▶ MockHandler.Handle
                 │
                 ├─① 读取契约快照（含当前场景，见场景快照机制）
                 ├─② 按 priority 遍历契约，用 matcher 匹配（方法/路径/头/查询/body）
                 ├─③ 命中？  ──否──▶ 404 {"code":40400,"message":"mock not found"} ─┐
                 │  是                                        ▲                     │
                 ├─④ responder.Render(场景响应模板, 请求上下文)                      │
                 ├─⑤ 渲染失败？──是──▶ fallback 响应(默认500) ──────────────────────┤
                 ├─⑥ 故障注入判定（概率/序号/固定错误）──命中──▶ 写故障响应 ─────────┤
                 ├─⑦ 延迟注入（固定/随机范围）                                        │
                 ├─⑧ 写出响应（状态码/头/体）                                        │
                 └─⑨ 异步提交调用记录（内存 channel → 批量入库） ──────────────────┘
```

## 5. 管理 API 处理时序

```
前端 ──JSON──▶ AdminHandler ──▶ ContractService ──▶ repository ──▶ SQLite
                  ▲                 │  校验规则(如 BR-1/BR-2)
                  └── 统一信封响应 {code, message, data}
```

管理操作均为同步事务，返回统一信封；错误码见 04-API设计。

## 6. 关键设计决策（ADR）

### ADR-1 为什么用 SQLite 而非 Postgres/MySQL
单文件零运维，符合"模拟服务"轻量定位；`modernc.org/sqlite` 为纯 Go 实现，`CGO_ENABLED=0` 可交叉编译；规模约束下不引入 ORM，手写 SQL 更可控。

### ADR-2 为什么场景切换走"快照"而非全局锁
模拟热路径上若每次请求都加全局锁读场景，会放大延迟。设计为：`ScenarioService` 持有 `atomic.Value` 缓存"契约 key → 场景快照"，切换时**重建快照并原子替换**；请求读取时 `Load()` 拿到不可变快照，天然并发安全（满足 BR-6 / NFR-4）。

### ADR-3 调用记录为什么异步落库
每次模拟调用若同步 INSERT，会显著抬高 P95 延迟。采用**有界内存队列（channel，容量 4096）+ 批量写入协程（每 100 条或 200ms flush）**；队列满时降级为同步直写并告警（满足 BR-7 / NFR-5）。

### ADR-4 为什么用原生 HTTP 而非 Gin/Echo
标准库路由（Go 1.22+ 支持 `{param}` 与通配）已满足 `{id}`、`*` 等路径需求；减少依赖即减少行数与风险，且更符合"行数可控"约束。

### ADR-5 为什么自研轻量迁移执行器
`golang-migrate` 等库依赖较重；需求仅需顺序执行内嵌 SQL + 记录版本。自研 60 行左右即可满足 NFR-3，且完全可控。

## 7. 依赖方向与禁止项

```
禁止：repository 调用 handler；service 直接写 SQL；matcher/responder 依赖 service。
约束：model 层零依赖；matcher/responder 仅依赖 model。
```
