# 03 数据库设计

## 1. 总览

- 数据库：SQLite（单文件，路径可配置，默认 `./data/mockbridge.db`）；
- 访问方式：`database/sql` + 手写 SQL（不引入 ORM）；
- 迁移：内嵌 `migrations/*.sql`，按文件名序执行，版本记录于 `schema_migrations` 表；
- 时区：所有时间字段统一存储 **UTC**，展示层转本地时区。

## 2. ER 模型

```
┌──────────────┐ 1        N ┌──────────────┐ 1       N ┌──────────────┐
│   contracts  │───────────▶│  scenarios   │──────────▶│  switch_logs │
│  (契约)      │            │  (场景)      │            │  (切换记录)   │
└──────────────┘            └──────────────┘            └──────────────┘
       1                              │
       │                              │ 1
       │                              ▼ N
       │                        ┌──────────────┐
       │                        │  call_records│◀── 模拟调用全量记录
       │                        └──────────────┘
       │                                    │
       │                                    ▼ N
       │                              ┌──────────────┐
       └──────────▶  call_stats ◀─────│  聚合统计     │
                     (契约+小时聚合)   └──────────────┘
```

## 3. 表结构定义

### 3.1 `schema_migrations`
```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version    INTEGER PRIMARY KEY,   -- 迁移版本号（文件名前缀）
    applied_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 3.2 `contracts` —— 契约表
```sql
CREATE TABLE contracts (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    key         TEXT    NOT NULL UNIQUE,      -- 全局唯一契约 key
    name        TEXT    NOT NULL,
    description TEXT    NOT NULL DEFAULT '',
    enabled     INTEGER NOT NULL DEFAULT 1,   -- 1 启用 / 0 禁用
    priority    INTEGER NOT NULL DEFAULT 100, -- 匹配优先级，越大越先匹配
    version     INTEGER NOT NULL DEFAULT 1,   -- 乐观锁版本
    created_at  TEXT    NOT NULL,
    updated_at  TEXT    NOT NULL
);
```
索引：`idx_contracts_priority ON contracts(priority DESC, id ASC)`

### 3.3 `scenarios` —— 场景表（响应定义 + 匹配规则 + 故障配置一体存储）
```sql
CREATE TABLE scenarios (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    contract_id       INTEGER NOT NULL REFERENCES contracts(id) ON DELETE CASCADE,
    name              TEXT    NOT NULL,           -- 场景名，同契约内唯一
    is_default        INTEGER NOT NULL DEFAULT 0, -- 是否默认场景
    is_active         INTEGER NOT NULL DEFAULT 0, -- 是否当前生效场景（每契约仅一个=1）
    match_rules_json  TEXT    NOT NULL DEFAULT '{}', -- 匹配规则（方法/路径/头/查询/body）
    response_status   INTEGER NOT NULL DEFAULT 200,  -- 响应状态码
    response_headers_json TEXT NOT NULL DEFAULT '[]',-- 响应头 [{"name":"...","value":"..."}]
    response_body     TEXT    NOT NULL DEFAULT '',   -- 响应体模板
    delay_fixed_ms    INTEGER NOT NULL DEFAULT 0,    -- 固定延迟
    delay_min_ms      INTEGER NOT NULL DEFAULT 0,    -- 随机延迟下界
    delay_max_ms      INTEGER NOT NULL DEFAULT 0,    -- 随机延迟上界
    fault_enabled     INTEGER NOT NULL DEFAULT 0,    -- 是否启用故障注入
    fault_status      INTEGER NOT NULL DEFAULT 500,  -- 故障响应状态码
    fault_body        TEXT    NOT NULL DEFAULT '{"code":50000,"message":"injected fault"}',
    fault_rate        REAL    NOT NULL DEFAULT 0,    -- 概率故障 0~1
    fault_on_calls    TEXT    NOT NULL DEFAULT '[]', -- 序号故障 [1,5,9]
    switch_after_calls INTEGER NOT NULL DEFAULT 0,   -- 命中 N 次后自动切换（0=不启用）
    switch_to_scenario_id INTEGER,                  -- 切往的目标场景
    switch_cron       TEXT    NOT NULL DEFAULT '',   -- 定时切换 cron（空=不启用）
    hit_count         INTEGER NOT NULL DEFAULT 0,    -- 当前场景累计命中次数
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);
```
索引：
```sql
CREATE UNIQUE INDEX idx_scenarios_contract_active ON scenarios(contract_id) WHERE is_active = 1;
CREATE INDEX idx_scenarios_contract ON scenarios(contract_id);
```

### 3.4 `call_records` —— 调用记录表
```sql
CREATE TABLE call_records (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    request_id     TEXT    NOT NULL,             -- 全局请求 ID（RequestID 中间件生成）
    method         TEXT    NOT NULL,
    path           TEXT    NOT NULL,
    query_string   TEXT    NOT NULL DEFAULT '',
    request_headers_json TEXT NOT NULL DEFAULT '[]',
    request_body   TEXT    NOT NULL DEFAULT '',  -- 截断 64KB
    client_ip      TEXT    NOT NULL DEFAULT '',
    contract_key   TEXT    NOT NULL DEFAULT '',  -- 命中契约；未命中为空
    scenario_name  TEXT    NOT NULL DEFAULT '',  -- 命中场景
    matched        INTEGER NOT NULL DEFAULT 0,   -- 是否命中
    match_detail   TEXT    NOT NULL DEFAULT '',  -- 匹配过程说明
    response_status INTEGER NOT NULL DEFAULT 0,
    response_headers_json TEXT NOT NULL DEFAULT '[]',
    response_body  TEXT    NOT NULL DEFAULT '',  -- 截断 64KB
    injected_delay_ms INTEGER NOT NULL DEFAULT 0,
    injected_fault INTEGER NOT NULL DEFAULT 0,   -- 是否注入故障
    total_ms       INTEGER NOT NULL DEFAULT 0,   -- 总耗时
    created_at     TEXT    NOT NULL
);
```
索引：
```sql
CREATE INDEX idx_records_created ON call_records(created_at);
CREATE INDEX idx_records_contract ON call_records(contract_key);
CREATE INDEX idx_records_status  ON call_records(response_status);
```

### 3.5 `switch_logs` —— 场景切换记录表
```sql
CREATE TABLE switch_logs (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    contract_key   TEXT NOT NULL,
    from_scenario  TEXT NOT NULL,
    to_scenario    TEXT NOT NULL,
    trigger_type   TEXT NOT NULL,  -- manual / after_calls / cron
    created_at     TEXT NOT NULL
);
```
索引：`CREATE INDEX idx_switch_logs_contract ON switch_logs(contract_key);`

### 3.6 `call_stats` —— 统计聚合表（后台任务写入）
```sql
CREATE TABLE call_stats (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    contract_key    TEXT NOT NULL,
    bucket_hour     TEXT NOT NULL,   -- 形如 2025-08-23T14:00:00Z
    total_calls     INTEGER NOT NULL DEFAULT 0,
    matched_calls   INTEGER NOT NULL DEFAULT 0,
    fault_calls     INTEGER NOT NULL DEFAULT 0,
    error_calls     INTEGER NOT NULL DEFAULT 0,   -- 状态码 >= 400
    sum_ms          INTEGER NOT NULL DEFAULT 0,   -- 总耗时，用于算平均
    UNIQUE(contract_key, bucket_hour)
);
```

## 4. 迁移策略

### 4.1 机制
1. 启动时 `database.Migrate(db)` 读取内嵌 `migrations/` 目录；
2. 按文件名数字前缀升序解析版本；跳过已存在于 `schema_migrations` 的版本；
3. 每个未应用版本在**同一事务**内执行 SQL + 写入版本记录，失败回滚并终止启动（fail-fast）；
4. 迁移文件内 SQL 使用 `IF NOT EXISTS` 等幂等写法，保证重复执行安全（NFR-3）。

### 4.2 版本清单
| 版本 | 文件名 | 内容 |
| --- | --- | --- |
| 1 | `migrations/0001_init.sql` | 上述全部表与索引 |

> 后续演进（示例）：`0002_add_contract_tags.sql` 增加标签列；`0003_backfill_stats.sql` 数据订正。实现阶段至少保留 1 个迁移文件，推荐 2~3 个（如拆分为 `0001_schema.sql`、`0002_seed_default.sql`）以证明迁移机制可用。

## 5. 数据一致性要点

- **级联删除**：删除契约 → `ON DELETE CASCADE` 自动删除其场景；切换记录与调用记录保留（历史可查）；
- **唯一生效场景**：`idx_scenarios_contract_active` 部分唯一索引保证每契约至多一个 `is_active=1`；
- **场景切换事务**：`UPDATE scenarios SET is_active=0 WHERE contract_id=? AND is_active=1; UPDATE ... SET is_active=1 WHERE id=?;` 两条在同一事务；
- **命中计数**：`hit_count` 的递增与"after_calls 自动切换判定"在**同一事务**内完成，避免并发双切换；
- **写入降级**：记录写入失败不阻断模拟响应（BR-7）。

## 6. 数据量估算与清理

- 单条调用记录约 1~4KB（含截断体），日调用 10 万条 ≈ 200~400MB，7 天保留期可接受；
- 清理任务：每 10 分钟 `DELETE FROM call_records WHERE created_at < datetime('now','-7 days')`，分批删除（每批 5000 行）避免长事务锁表；
- 统计表按 (contract_key, bucket_hour) 保留 30 天。
