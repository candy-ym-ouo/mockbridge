# 07 后台任务设计

## 1. 任务清单

| 任务 | 周期 | 职责 | 需求 |
| --- | --- | --- | --- |
| `scenario-switcher` | 每 30 秒扫描 | 按 `switch_cron` 表达式执行契约场景定时切换 | FR-4.4 / FR-7.1 |
| `record-cleaner` | 每 10 分钟 | 删除超过保留期（默认 7 天，可配）的调用记录 | FR-5.4 / FR-7.2 |
| `stats-aggregate` | 每 5 分钟 | 将上一小时调用记录聚合写入 `call_stats` | FR-7.3 |

## 2. 调度器（worker/scheduler.go）

### 2.1 结构
```go
type Job interface {
    Name() string
    Run(ctx context.Context) error   // 单次执行，返回错误由调度器记录
}

type Scheduler struct {
    jobs   []scheduledJob   // {job, interval}
    logger *slog.Logger
    lastRun sync.Map        // name → runInfo{lastRunAt, lastError}
    done    chan struct{}
}
```

### 2.2 调度逻辑
```
Start(ctx):
  for each job: go loop(ctx, job)
  <-ctx.Done() → 等待所有 loop 退出（WaitGroup）→ close(done)

loop(ctx, job):
  ticker = time.NewTicker(job.interval)
  defer ticker.Stop()
  for {
     select {
     case <-ctx.Done(): return
     case <-ticker.C:
        err := job.Run(ctx)
        lastRun.Store(job.Name(), {now, err})   // 供 /admin/api/health 读取
        if err != nil: logger.Error("job failed", "job", job.Name(), "err", err)
     }
  }
```
- 间隔从配置读取（`tasks.cleaner_interval` 等），默认值见下表；
- 单任务执行超过间隔时跳过下一次 tick（不叠加），保证不堆积；
- 优雅停止：ctx 取消后正在执行的 Run 应立即检查 ctx 并返回（如清理任务分批之间检查）。

## 3. scenario-switcher 任务

```
Run(ctx):
  1. rows = SELECT id, contract_key, name, switch_cron FROM scenarios
            WHERE switch_cron != '' AND is_active = 1
  2. for row in rows:
        if cronMatch(row.switch_cron, time.Now()):   // 分钟级匹配，如 "*/5 * * * *"
            ScenarioService.SwitchTo(row.contractKey, 目标场景?, trigger="cron")
  3. 无目标场景配置时：切换记录写 "cron" 触发、目标为默认场景
```
- **cron 表达式简化实现**：仅支持 5 段 `分 时 日 月 周`，支持 `*`、`*/N`、逗号列表；不引入第三方 cron 库（规模约束）；
- 匹配逻辑：当前时刻的 分/时/日/月/周 是否落在表达式集合内，取整分钟边界触发，避免重复触发（记录上次触发分钟，同分钟不重复执行）；
- 目标场景：优先取 `switch_to_scenario_id`，为空则切换回默认场景；
- 切换失败（场景不存在等）记错误日志，不影响其他契约。

## 4. record-cleaner 任务

```
Run(ctx):
  before = now - retention (默认 7d, 配置 tasks.record_retention_days)
  loop:
     n = DELETE FROM call_records WHERE created_at < before LIMIT 5000
     if n == 0 or ctx.Err() != nil: break
     time.Sleep(100ms)   // 给写事务让路
  logger.Info("cleaner done", "removed", total)
```
- 分批删除避免长事务锁表（SQLite 单写者特性下尤为重要）；
- 手动清理接口复用同一 repository 方法（`POST /admin/api/records/clean`）。

## 5. stats-aggregate 任务

```
Run(ctx):
  bucket = 上一整点小时  // 例如 14:05 执行时聚合 13:00~13:59
  1. rows = SELECT contract_key,
                   COUNT(*) AS total, SUM(matched) AS matched,
                   SUM(injected_fault) AS faults,
                   SUM(CASE WHEN response_status >= 400 THEN 1 ELSE 0 END) AS errors,
                   SUM(total_ms) AS sum_ms
            FROM call_records
            WHERE created_at >= bucket AND created_at < bucket+1h
            GROUP BY contract_key
  2. for row in rows:
        INSERT INTO call_stats (contract_key, bucket_hour, ...)
        VALUES (...) ON CONFLICT(contract_key, bucket_hour) DO UPDATE SET ...
  3. 删除 30 天前的统计行
```
- **幂等**：同一 bucket 重复执行是 upsert 覆盖，天然可重跑（补数）；
- 当前小时数据由 overview 接口实时查询补充（避免仪表盘滞后一小时）。

## 6. 健康状态暴露

`/admin/api/health` 的 `tasks` 字段直接读取 `Scheduler.lastRun`：
```json
{ "name": "stats-aggregate", "last_run_at": "2025-08-23T14:35:00Z", "last_error": "" }
```
- 任务超过 2 个周期未运行（如 last_run_at 过旧）时，健康状态降级为 `degraded`。

## 7. 并发与安全设计

- 所有任务共享同一 `ScenarioService` / repository 实例，内部使用事务与锁保证一致性；
- cron 切换与 after_calls 切换可能并发：两者都走"切换事务 + 快照替换"，以事务先后为准，最终一致；
- 任务错误不 panic：Run 返回 error 由调度器捕获记录；panic 由任务内 recover 兜底后转为 error 返回；
- 测试策略：任务逻辑抽成可注入 repository 的纯函数（如 `cleanBefore(db, before, batch)`），单元测试覆盖，调度循环本身仅做冒烟测试。
