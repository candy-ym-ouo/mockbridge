# 08 测试与构建验证

## 1. 测试分层策略

| 层级 | 对象 | 手段 | 覆盖目标 |
| --- | --- | --- | --- |
| 单元测试 | matcher / responder / scenario（纯逻辑） | 表驱动用例 | 各匹配维度、模板语法、切换判定 |
| 服务测试 | service 层 | 内存 SQLite + repository | 业务规则（BR-1~BR-10） |
| 集成测试 | handler 层 + 完整服务 | `httptest.Server` 全链路 | 模拟入口、管理 API、记录落库、故障延迟 |
| 并发测试 | 场景切换 + 热路径 | `-race` + 并发 goroutine | 快照原子性、无数据竞争 |
| 迁移测试 | database 层 | 临时库执行迁移两次 | 幂等性（NFR-3） |

## 2. 单元测试用例清单（核心）

### 2.1 matcher（`internal/matcher/*_test.go`）
| 用例 | 断言 |
| --- | --- |
| 方法精确匹配 | GET 规则命中 GET，不命中 POST |
| 方法通配 `*` | 命中任意方法 |
| 路径精确/参数/通配 | `{id}` 捕获正确；`/**` 命中子路径；`*` 单段不越段 |
| 路径不匹配 | 返回未命中且 detail 含未满足维度 |
| 头/查询/body 组合 AND | 缺一条件即不命中 |
| JSONPath body 匹配 | 嵌套取值、数组下标、期望值通配 |
| 非 JSON body 含 body 规则 | 不命中、不 panic |
| 优先级排序 | 高 priority 先命中 |
| 命中 detail 文案 | 含 "matched: method,path" 等 |

### 2.2 responder（`internal/responder/*_test.go`）
| 用例 | 断言 |
| --- | --- |
| `{{request.query.name}}` 注入 | 输出含查询参数值 |
| `{{path.id}}` 注入 | 输出含路径参数 |
| `{{uuid()}}`/`{{now()}}`/`{{randInt}}` | 格式合法（UUID 正则/时间格式/数值范围） |
| `{{state.counter}}` 注入 | 输出为快照计数 |
| 响应头模板替换 | 头值变量被求值 |
| 渲染失败 → fallback | 返回 500 + 错误体 |
| body 超 1MB | 触发 fallback |
| `\{{` 转义 | 输出字面 `{{` |
| 非法状态码 | fallback 500 |

### 2.3 scenario（`internal/service/scenario_service_test.go` 覆盖）
| 用例 | 断言 |
| --- | --- |
| after_calls 达标自动切换 | 命中 N 次后 is_active 变更且写 switch_logs |
| 未达标不切换 | 第 N-1 次仍为原场景 |
| 并发切换唯一性 | 50 并发激活不同场景，最终仅一个生效（配合 race） |
| 删除生效场景回退默认 | 默认场景自动 is_active=1 |

## 3. 集成测试用例（`internal/handler` 或 `test/`）

| 用例 | 步骤 | 断言 |
| --- | --- | --- |
| 全链路命中 | 建契约→建场景→发匹配请求 | 返回模板渲染结果，记录落库 |
| 未命中 404 | 发不匹配请求 | 40400 信封，记录 matched=false |
| 故障注入 | 场景 fault_rate=1 | 返回 503 故障体，记录 injected_fault=true |
| 延迟注入 | 场景固定延迟 300ms | 响应耗时 ≥ 300ms，记录 injected_delay_ms=300 |
| 场景切换热更新 | 激活场景 B 后立即请求 | 请求命中新场景响应（快照生效） |
| 契约删除级联 | 删除契约 | 场景消失，模拟入口 404 |
| 乐观锁冲突 | version 旧值 PUT | 40900 |
| 迁移幂等 | 同一临时库执行两次 Migrate | 第二次无变更、不报错 |
| 记录清理 | 手工插入旧记录 + 触发 cleaner | 旧记录删除、新记录保留 |

## 4. 覆盖率目标（NFR-6）

| 包 | 目标行覆盖率 |
| --- | --- |
| internal/matcher | ≥ 85% |
| internal/responder | ≥ 80% |
| internal/service | ≥ 75% |
| internal/repository | ≥ 60% |
| internal/handler | ≥ 60% |
| 全局 | ≥ 70% |

> 覆盖率统计不含 worker 调度循环与 main.go 装配代码（冒烟覆盖即可）。

## 5. 构建与验证流水线（make verify）

```
make verify 由以下目标串行组成（任一失败即退出非 0）：

1. make fmt        → gofmt -l . 为空
2. make vet        → go vet ./...
3. make lint       → go vet 增强检查（或 staticcheck，如允许引入）
4. make test       → go test ./... -race -coverprofile=coverage.out
                     （-race 覆盖 NFR-4；输出覆盖率并校验 ≥70%）
5. make build      → go build -o bin/mockbridge ./cmd/server
                     （CGO_ENABLED=0 交叉编译检查 linux/amd64 可选）
6. make check-size → scripts/linecount.sh：Go 非测试代码行数 2000 < L < 2200
                     且文件数 20 < F < 25（详见 09 文档）
7. make smoke      → 启动 bin/mockbridge，curl 冒烟：
                     - GET /admin/api/health → ok
                     - 建契约→模拟请求→命中→记录可查（一条龙脚本）
```

### Makefile 目标一览（实现阶段落地）
```makefile
.PHONY: build test vet fmt lint verify smoke migrate run clean
```

## 6. 验收执行的自动化脚本（scripts/verify.sh 规划）

1. `make verify` 全绿；
2. `scripts/linecount.sh` 输出两类报告：`total Go LOC = 21xx`（合规）、`files = 22`（合规）；
3. 冒烟脚本输出关键步骤 `[PASS]` / `[FAIL]` 清单。

## 7. 测试与约束的冲突预案

- 若实现后行数逼近下界 2000：优先补充 matcher/responder 边界用例逻辑与 handler 明细分支（如分页参数校验），并在 09 文档预算表登记追加来源；
- 若逼近上界 2200：优先压缩 repository 层重复 SQL 样板（抽公共 helper），严禁砍测试或合并文件降文件数；
- 行数计量口径以 09 文档第 3 节为准，任何调整需同步更新 09 文档预算表。
