# 01 需求分析

## 1. 项目背景与问题陈述

在前后端并行开发、第三方系统联调、故障演练等场景中，后端接口常常不可用、未就绪或行为不稳定，导致：

1. **前端阻塞**：依赖的后端接口未开发完成，前端无法联调；
2. **测试脆弱**：联调依赖真实环境，无法稳定复现特定响应（超时、错误、边界值）；
3. **演练困难**：无法按需注入延迟、5xx、特定返回体，故障演练只能靠运气；
4. **契约失控**：接口参数、返回结构没有统一的可执行契约，改动难以追踪。

**解决思路**：构建一个"接口契约模拟服务"——把接口的请求匹配规则、响应内容、场景状态、故障行为作为**可配置的契约**保存下来，用真实 HTTP 服务对外提供与真实后端一致的接口行为，同时提供管理 API 与后台界面进行契约管理和运行观测。

### 1.1 定位边界（不是什么）

- ❌ 不是简易 Mock：不是"路径 → 固定 JSON 字符串"的映射表，而是具备匹配引擎、模板引擎、状态机（场景）、记录与故障注入的完整服务；
- ❌ 不是 API 网关：不做鉴权转发、限流熔断、流量治理，仅聚焦"模拟"语义；
- ❌ 不是录制回放工具：不自动抓包生成契约，契约由人工或管理 API 配置。

## 2. 用户与用户故事

| 角色 | 痛点 | 期望 |
| --- | --- | --- |
| 前端工程师 | 后端未就绪，联调阻塞 | 按契约快速模拟接口，含各种边界返回 |
| 测试工程师 | 难以稳定复现异常场景 | 一键切换场景（成功/超时/500/空数据），观察调用记录 |
| 后端工程师 | 下游依赖不可控 | 配置模拟响应验证自身容错逻辑，注入延迟观察超时处理 |
| 运维/负责人 | 无法了解模拟服务运行状况 | 仪表盘查看契约数、调用量、故障分布 |

### 用户故事清单

- US-01 作为前端工程师，我可以创建一条契约并配置匹配规则，使请求按规则命中并返回动态响应；
- US-02 作为测试工程师，我可以在同一契约下配置多个场景，并通过界面一键切换当前生效场景；
- US-03 作为后端工程师，我可以为契约配置延迟与故障注入，验证自身超时/重试逻辑；
- US-04 作为任何使用者，我可以查询每次调用的完整记录（请求、响应、匹配过程、耗时）；
- US-05 作为负责人，我可以查看概览统计（总调用、失败率、平均耗时、场景分布）。

## 3. 功能需求（FR）

### FR-1 契约管理（Contract Management）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-1.1 | 创建/编辑/删除/查询契约，契约以 `key`（全局唯一）标识，key 形如 `user/get-profile` | P0 |
| FR-1.2 | 契约包含：名称、描述、`key`、启用状态、默认场景引用 | P0 |
| FR-1.3 | 契约可整体启用/禁用；禁用后请求直接返回 404 并不再记录 | P0 |
| FR-1.4 | 契约变更记录 `updated_at` 与 `version`，支持乐观锁防并发覆盖 | P1 |

### FR-2 请求匹配（Request Matching）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-2.1 | 匹配规则支持以下维度，全部维度需同时满足（AND 语义）才算命中： | P0 |
| FR-2.1.1 | **方法**：`GET/POST/PUT/DELETE/PATCH`，或 `*` 通配任意方法 | P0 |
| FR-2.1.2 | **路径**：精确路径、`{id}` 路径参数、`*` 通配段、尾通配 `/**` | P0 |
| FR-2.1.3 | **请求头**：`headerName: value`，支持通配值 | P1 |
| FR-2.1.4 | **查询参数**：`queryKey: value`，支持通配值 | P1 |
| FR-2.1.5 | **JSON Body**：`jsonpath: expectedValue` 表达式，支持嵌套取值与通配 | P0 |
| FR-2.2 | 多条契约按 `priority` 降序匹配；同优先级按创建时间升序；全部不命中返回 `404 Mock Not Found` | P0 |
| FR-2.3 | 匹配过程（命中/未命中/命中哪条规则）必须写入调用记录 | P0 |

### FR-3 动态响应（Dynamic Response）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-3.1 | 每个场景包含响应定义：状态码、响应头集合、响应体模板 | P0 |
| FR-3.2 | 响应体模板支持变量注入： | P0 |
| FR-3.2.1 | 请求上下文：`{{request.method}}`、`{{request.path}}`、`{{request.query.name}}`、`{{request.header.X-Token}}`、`{{request.body.userId}}`（JSONPath） | P0 |
| FR-3.2.2 | 路径参数：`{{path.id}}` | P0 |
| FR-3.2.3 | 内置函数：`{{uuid()}}`、`{{now()}}`、`{{randInt(1,100)}}`、`{{randStr(8)}}`、`{{timestamp()}}` | P1 |
| FR-3.2.4 | 场景状态：`{{state.counter}}`（可被脚本/后台任务修改，实现"第 N 次返回 X"） | P1 |
| FR-3.3 | 支持响应模板命中时 JSON 合法性与大小校验（>1MB 拒绝） | P2 |
| FR-3.4 | 支持 **fallback 响应**：当模板渲染失败时按配置返回兜底响应（默认 500 + 错误体） | P0 |

### FR-4 场景切换（Scenario Switching）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-4.1 | 每个契约下可配置 1..N 个场景，场景含名称、是否默认、响应定义、延迟与故障配置 | P0 |
| FR-4.2 | 手动切换：通过管理 API/前端将某契约的当前场景切换为指定场景，立即生效 | P0 |
| FR-4.3 | 自动切换（次数触发）：配置 `switch_after_calls=N`，当前场景被命中 N 次后自动切到 `switch_to` 场景，并写一条切换记录 | P1 |
| FR-4.4 | 自动切换（定时触发）：配置 `switch_at="15:30"`（每日）或 `switch_cron="*/5 * * * *"`，由后台调度器执行 | P1 |
| FR-4.5 | 场景切换是**原子操作**：并发请求下每次调用读取到的是"某一时刻的完整场景快照" | P0 |
| FR-4.6 | 切换记录（时间、契约、从→到、触发方式）可查询 | P1 |

### FR-5 调用记录（Call Records）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-5.1 | 每次进入模拟服务的请求（无论是否命中契约）均落库一条记录 | P0 |
| FR-5.2 | 记录字段：请求行/头/体（体截断 64KB）、命中契约 key、命中场景、匹配耗时、响应状态码、响应体（截断 64KB）、总耗时、客户端 IP、时间戳 | P0 |
| FR-5.3 | 提供分页查询 API：按契约 key、状态码、时间段、关键字过滤 | P0 |
| FR-5.4 | 记录默认保留 7 天，由清理任务定期删除（见 FR-7） | P1 |
| FR-5.5 | 记录写入采用**异步落库**（内存队列 + 批量写），避免影响模拟响应延迟 | P0 |

### FR-6 延迟与故障注入（Latency & Fault Injection）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-6.1 | 场景可配置**固定延迟**（ms），生效于响应写出之前 | P0 |
| FR-6.2 | 场景可配置**随机延迟范围** `min_ms ~ max_ms`（均匀分布） | P1 |
| FR-6.3 | 场景可配置**故障注入**： | P0 |
| FR-6.3.1 | 错误响应：覆盖状态码与响应体（如 500/503/429 + 错误 JSON） | P0 |
| FR-6.3.2 | 概率故障：`fault_rate=0.1` 表示 10% 请求返回故障响应 | P0 |
| FR-6.3.3 | 序号故障：`fault_on_calls=[1,5,9]` 表示第 1/5/9 次调用返回故障 | P1 |
| FR-6.4 | 连接中断模拟：`abort_connection=true` 时直接关闭连接不写响应（模拟断连） | P2 |
| FR-6.5 | 故障与延迟对**调用记录可见**：记录标注 `injected_delay_ms`、`injected_fault` 字段 | P0 |

### FR-7 后台任务（Background Tasks）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-7.1 | **场景定时切换调度器**：按 `switch_cron` 执行契约场景切换 | P1 |
| FR-7.2 | **记录清理任务**：每 10 分钟删除超过保留期的调用记录，支持保留期可配 | P1 |
| FR-7.3 | **统计聚合任务**：每 5 分钟将调用记录按契约+小时聚合写入统计表，供仪表盘读取（避免实时 COUNT 大表） | P1 |
| FR-7.4 | 任务统一注册到调度器，支持优雅停止（ctx 取消）与错误日志 | P0 |
| FR-7.5 | 任务运行时提供 `GET /admin/api/health/tasks` 返回各任务最近执行时间与状态 | P2 |

### FR-8 管理后台与前端（Admin UI）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-8.1 | 前端为服务端托管的静态页面，无构建链，原生 HTML/CSS/JS | P0 |
| FR-8.2 | 页面：概览仪表盘、契约列表/编辑、场景控制台（切换场景）、调用记录、健康状态 | P0 |
| FR-8.3 | 前端调用管理 API 完成全部管理操作（不直连数据库） | P0 |
| FR-8.4 | 界面为中文，响应式基础布局 | P1 |

## 4. 非功能需求（NFR）

| 编号 | 需求 | 验收方式 |
| --- | --- | --- |
| NFR-1 | **代码规模**：Go 非测试代码 2000 < L < 2200 行；文件数 20 < F < 25 | `make verify` 中计量脚本校验 |
| NFR-2 | 分层架构：handler → service → repository → database 单向依赖，禁止反向 | 依赖检查 + code review |
| NFR-3 | 数据库迁移：版本化 SQL 迁移文件，`migrate up` 可重复执行（幂等） | `make migrate` + 测试 |
| NFR-4 | 并发安全：模拟路径与场景切换并发安全（场景快照读） | `go test -race` 通过 |
| NFR-5 | 性能基线：模拟响应 P95 延迟 < 20ms（本机、无注入延迟时） | 压测脚本记录 |
| NFR-6 | 测试覆盖：核心包（matcher/responder/service）行覆盖率 ≥ 70% | `go test -cover` |
| NFR-7 | 构建验证：`make verify` 一键完成 format/vet/lint/test/race/build/规模计量 | 全绿 |
| NFR-8 | 服务可配置端口、数据库路径、日志级别、保留期等 | config.yaml |
| NFR-9 | 优雅停机：SIGTERM 后停止接收新请求、等待在途请求完成、停止后台任务 | 手工验证 |

## 5. 业务规则汇总（Business Rules）

以下规则为全局不变量，实现时必须在对应模块强制：

| 规则 | 说明 | 违反后果 |
| --- | --- | --- |
| BR-1 | 契约 `key` 全局唯一，格式 `^[a-z0-9][a-z0-9/_-]{0,127}$` | 创建时校验，409 |
| BR-2 | 每个契约必须有且仅有一个默认场景（创建契约时自动生成 `default` 场景） | 契约不可无场景 |
| BR-3 | 场景引用契约必须存在，禁止孤儿场景（删除契约级联删除场景） | 事务保证 |
| BR-4 | 匹配顺序：priority 降序 → created_at 升序 → key 升序（稳定） | 调用记录标注 |
| BR-5 | 延迟注入与故障注入是"响应写出前"的最后两步，顺序：渲染 → 故障 → 延迟 → 写出 | 记录注入字段 |
| BR-6 | 场景切换为原子操作，读取场景一律走"快照" | race 测试 |
| BR-7 | 调用记录写入失败不影响响应返回（best-effort） | 日志告警 |
| BR-8 | 所有管理 API 返回统一信封 `{code, message, data}` | API 契约 |
| BR-9 | 删除/停用契约后，模拟入口对该 key 立即 404 | 一致性测试 |
| BR-10 | 模板渲染失败时走 fallback 响应，绝不 panic | 恢复中间件兜底 |

## 6. 需求范围外（Out of Scope）

- 用户登录/权限体系（管理 API 不做鉴权，仅限内网使用）；
- 契约自动录制（从真实流量生成契约）；
- 多租户与集群部署、分布式场景切换同步；
- HTTPS/TLS 终止、国际化多语言界面。
