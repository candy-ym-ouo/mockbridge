# 06 前端界面设计

## 1. 定位与技术方案

- 定位：**简单管理后台**，让使用者可视化完成契约管理、场景切换、调用观测、健康检查；
- 技术：服务端托管的静态页面（`web/` 目录），**原生 HTML + CSS + JavaScript（ES2017）**，无构建链、无框架、无 npm 依赖；
- 托管：Go 服务器 `GET /admin/` → `web/index.html`；`GET /admin/static/*` → 静态文件；
- 通信：`fetch` 调用管理 API（见 04 文档），统一处理信封 `{code, message, data}`；
- 单页应用 + 简单 hash 路由（`#/contracts`、`#/records`、`#/dashboard`），刷新不丢失状态。

## 2. 页面清单

| 页面 | 路由 | 核心功能 | 依赖 API |
| --- | --- | --- | --- |
| 概览仪表盘 | `#/dashboard` | 统计卡片、TOP 契约、调用趋势图 | stats/overview、stats/trend、health |
| 契约列表 | `#/contracts` | 分页列表、搜索、启用/禁用、删除、新建入口 | contracts list/delete |
| 契约编辑 | `#/contracts/{key}` | 契约基本信息 + 场景列表 + 场景编辑表单 | contracts detail/update、scenarios CRUD |
| 场景控制台 | `#/contracts/{key}/scenarios` | 切换当前场景（一键激活）、查看各场景状态 | scenarios activate |
| 调用记录 | `#/records` | 分页查询、过滤（契约/状态码/时间段/关键字）、详情抽屉 | records list/detail |
| 健康检查 | `#/health` | 服务状态、任务运行情况、队列深度 | health |

## 3. 页面交互设计

├──────────┴──────────┴──────────┴──────────┴──────────┤
│  TOP 契约（近 24h）         │  调用趋势（近 24h，小时柱状）   │

- 进入页面即并行请求 `stats/overview` 与 `health`，失败时卡片显示 `--` 与红色告警条；

### 3.2 契约列表与编辑
```
契约列表:
  [搜索框: user] [仅看启用 ☑]          [＋ 新建契约]
  ┌──────┬──────────────┬────────┬────────┬────────┬──────┐
  │ key  │ 名称          │ 优先级  │ 生效场景 │ 启用   │ 操作  │
  │ ...  │ ...          │ 100    │ timeout │ ☑切换  │ 编辑/删│
  └──────┴──────────────┴────────┴────────┴────────┴──────┘

新建契约弹窗:
  字段: key / name / description / priority
  提交 → POST /admin/api/contracts → 自动生成 default 场景 → 跳转编辑页

契约编辑页（左侧契约信息，右侧场景管理）:
  ┌ 契约信息 ─────────────────────────────────────────┐
  │ name [____] description [__________] priority[100] │
  │ 版本 v1  [保存]（并发冲突时提示刷新重试）              │
  ├ 场景列表 ─────────────────────────────────────────┤
  │ ● success (默认)  [生效中] [编辑] [删除]            │
  │ ○ timeout         [激活▶]   [编辑] [删除]           │
  │ ○ error           [激活▶]   [编辑] [删除]           │
  │ [+ 新增场景]                                        │
  └────────────────────────────────────────────────────┘

场景编辑表单（弹窗或内联展开）:
  匹配规则:  方法[GET▾] 路径[/api/v1/user/{id}]
             请求头 [X-Token = test-*]  [+添加]
             查询参数 [type = vip]       [+添加]
             JSON Body [$.userId = 1001] [+添加]
  响应定义:  状态码[200] 响应头 [Content-Type=application/json] [+]
             响应体模板 [textarea: {"id":{{path.id}},"token":"{{uuid()}}"}]
  延迟故障:  固定延迟[0ms] 随机范围[0~0ms]
             故障开关[☐] 状态码[503] 概率[0.5] 序号[1,5,9]
  自动切换:  命中N次后[0] 切往[error▾] 定时cron[ ]
```
- "激活▶"按钮点击后调用 activate API，成功后高亮该场景并刷新列表（**场景控制台与编辑页合一**）；
- 删除当前生效场景时后端自动回退默认场景，前端提示并刷新。

### 3.3 调用记录
```
筛选栏: 契约key[▾下拉] 状态码[200▾] 命中[全部/是/否] 时间[近1小时▾] 关键字[____] [查询]
表格: 时间 | 请求ID | 方法 | 路径 | 契约 | 场景 | 状态 | 延迟 | 故障 | 耗时
行点击 → 右侧抽屉:
  ┌ 请求详情 ─────────────────────────┐
  │ method/path/query/headers/body    │
  │ 匹配过程: priority=100 matched... │
  │ 响应: status/headers/body         │
  │ 注入: delay=250ms fault=true      │
  └───────────────────────────────────┘
```
- 分页控件：上一页/下一页 + 页码 + 总数；查询条件变化自动重置到第 1 页；
- 详情抽屉里 body 超过 2KB 折叠显示。

## 4. 前端代码结构（web/）

| 文件 | 职责 | 估算行数 |
| --- | --- | --- |
| `web/index.html` | 页面骨架、导航、各页容器、弹窗模板 | ~180 |
| `web/style.css` | 布局、卡片、表格、表单、弹窗、趋势条样式 | ~220 |
| `web/app.js` | hash 路由、fetch 封装、各页面渲染与事件、状态管理 | ~480 |

> 前端不计入 Go 代码规模约束（约束仅针对 `*.go` 非测试文件）。

## 5. 前端与后端的约定

- 所有写操作（创建/更新/删除/激活）成功后刷新当前数据源，不乐观更新（保持简单）；
- `app.js` 中封装 `api(path, method, body)`：解析信封，`code!==0` 时 `alert(message)` 并 reject；
- 加载中状态：按钮禁用 + "处理中..."；错误状态：顶部红色横幅显示最近错误；
- 页面默认路由 `#/dashboard`；所有时间展示为浏览器本地时区（`toLocaleString`）。

## 6. 验收点（前端相关）

- [ ] 无构建链：`go run` 启动后直接访问 `/admin/` 即可使用全部管理功能；
- [ ] 五大页面完整可用，增删改查与场景切换闭环可操作；
- [ ] 所有管理操作经由管理 API，无直连数据库逻辑；
- [ ] 接口响应失败有明确提示，不出现白屏。
